# Checkpoint NN — Title

| Field | Value |
|---|---|
| Status | Planned \| In progress \| In review \| Complete |
| Date | YYYY-MM-DD |
| Branch | `branch-name` |
| Pull request | URL or Not applicable |
| Implementation commit | commit or Pending |

## Objective

State the concrete outcome in one or two sentences.

## Why this checkpoint comes next

Explain the prioritization. Describe which later work depends on this foundation and why postponing it would increase risk or rework.

## Starting condition

Describe the relevant behavior before the change. Separate confirmed facts from assumptions.

## Plan

1. List the bounded implementation steps.
2. Include validation and documentation.
3. State intentionally deferred work.

## Decisions and alternatives

For each meaningful decision, record:

- **Decision:** What was selected.
- **Reason:** Why it fits this context.
- **Alternatives:** What else was considered.
- **Tradeoff:** What the selected approach does not optimize for.
- **Revisit when:** Evidence or conditions that should trigger reconsideration.

## Implementation outcome

Summarize what actually changed. Note any divergence from the plan and why.

## Validation evidence

Record tests, static checks, manual verification, and relevant failure cases. Do not say only “tested successfully”; preserve enough evidence to understand what was demonstrated.

## Senior-engineering lessons

Explain the principles behind the implementation, including boundaries, failure modes, maintainability, security, cost, and operational concerns where relevant.

## Applying this elsewhere

Provide a short checklist for recognizing and applying these lessons in another project.

## Common mistakes

Record tempting approaches that would create hidden risk or complexity and explain why.

## Explain-back questions

List questions that can be answered without looking at the implementation. The goal is to verify understanding, not memorization.

## Deferred work

List related changes intentionally excluded from this checkpoint and identify the checkpoint that should own them when known.
